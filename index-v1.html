Why this exists

Half the Joomla world runs 3.x. Support for it ended.

According to market share estimates (May 2026), Joomla 3.x is used on more than 50% of all installed Joomla sites worldwide — yet official support ended in February 2025, counting the eLTS program. Joomla 3.x UTD continues development where official support stopped: keeping code secure, compatible with the PHP and database versions your servers actually ship with, and fixing long-standing broken behaviour along the way.

[security]

Backported security patches

CVE fixes reported after Joomla 3.10.20 eLTS, plus security patches backported from Joomla 4, 5 and 6 — including ones labelled “4.0.0+ only” upstream where the vulnerable code exists in 3.x regardless.

[compat]

Modern PHP & databases

Runs on PHP up to 8.5 (7.4 recommended baseline, updates offered down to 7.1) and works with MySQL 8.x and current MariaDB.

[drop-in]

Drop-in upgrade

Update from the Joomla backend, or extract on top of any existing Joomla 3.x installation. Your templates, extensions and content stay exactly as they are.

Install & upgrade

From zero — or on top of an existing site.

1

Fresh install

Extract the latest rolling release where you want the site to live, then follow the normal Joomla installation process.

download url
https://github.com/joomlaworks/joomla-3.x/releases/download/rolling/joomla-latest.zip
2

Upgrade an existing site — Web UI

The easiest path: point the Joomla Update component at this distribution's feed (see staying current below), refresh, and update in place from the backend.

3

Upgrade an existing site — CLI

Extract the same archive on top of an existing Joomla 3.x installation, then remove the /installation folder. On a typical Linux server, it's a one-liner after you cd into your site's folder:

shell
wget -qO- https://github.com/joomlaworks/joomla-3.x/archive/refs/heads/main.tar.gz | tar -xz --strip-components=1 && rm -rf installation .github .gitignore *.md
4

Verify

Log into the administrator backend and check System → System Information — the version string should match the latest release. Then visit Extensions → Manage → Database and fix the schema if prompted.

PHP compatibility. This distribution targets at least PHP 7.4 — the recommended baseline for broader hosting and ecosystem compatibility. Sites on PHP 7.1–7.3 are still offered updates so they keep receiving security patches; PHP 7.0 and below is not supported.
Built for Linux/BSD. This distribution is developed and tested on Linux/BSD systems only. XAMPP or MAMP on Windows/macOS should work, but is not tested.

Staying current

In-place updates, straight from the backend.

Starting with v3.12, this distribution ships its own update feed. Sites on v3.12 or newer get update notifications automatically through Components → Joomla Update — no manual work needed. Running v3.11 or earlier? Point the Joomla Update component at this distribution's feed once:

Set these under the Joomla Update component's Options (or in Global Configuration). Once you're on v3.12+, future updates are detected and applied automatically.

Database notes

MySQL 8.x & MariaDB configuration

For Joomla 3.x to work flawlessly with MySQL 8.0 or newer, enable native password authentication in your my.cnf. Use one block or the other — not both. These settings do not apply to MariaDB.

my.cnf — MySQL 8.0
# For MySQL 8.0 only
default_authentication_plugin = mysql_native_password
my.cnf — MySQL 8.4+
# For MySQL 8.4+
mysql_native_password = ON
authentication_policy = mysql_native_password

For maximum compatibility on both MySQL and MariaDB, we also recommend:

my.cnf — MySQL & MariaDB
sql_mode = ""

Long-term plan

A leaner fork is on the way.

Beyond keeping 3.x patched, a new fork based on Joomla 3.x is in very active development — a separate project focused on being a solid, backwards-compatible platform for building sites.

Stripped-down core

All non-essential extensions removed. com_content and everything related is replaced by K2 for content, decoupling content features from the CMS base.

Full PHP 7.4 → 8.x compatibility

Plus full compatibility with the latest MySQL & MariaDB versions, maintained without much effort as new releases land.

Admin refresh

A modernized administrator experience on top of the familiar workflow.

Modern JavaScript only

Gradual removal of jQuery and MooTools, alongside broader codebase modernization for future PHP & database versions.
