        // new in v3.17
        
The biggest release yet

        
Every major database, a new installer, three new templates and a command line built for scripts and AI assistants — on top of 22 security fixes and a long list of bugs that stock Joomla 3 never fixed.

      

      Full changelog →
    


    

      

        new sites
        
A brand new installer

        
An app-style installer with a sidebar of steps, dark mode and right-to-left support, built with plain HTML, CSS and JavaScript. Same steps as before, every database driver, and it cleans up after itself.

        
    
          
  • MySQL, MariaDB, PostgreSQL, SQL Server & Azure SQL, and SQLite
    • 
          
  • Three sample data sets, each with its own template: News, Blog and Studio
    • 
          
  • Removes the installation folder for you when you continue to the site
    • 
          
  • Locked once installed: only the browser that installed the site can go on
    • 
        

      

      
    


    

      

        databases
        
Every major database

        
MySQL and MariaDB (native & PDO), PostgreSQL (native & PDO, fixed for PHP 8.1+), SQL Server & Azure SQL, all tested. MySQL 8.0, 8.4 and 9.x work on their default authentication, with no my.cnf changes.

        Database support →
      

      

        sqlite · experimental
        
A whole site in one file

        
The new SQLite driver runs Joomla's and your extensions' MySQL SQL unchanged, through WordPress' emulation layer. Spin up dev sites in seconds, or keep a site in Dropbox and pick it up on another machine.

        SQLite notes →
      

      

        frontend
        
Three new templates

        
Hammond for news, Finch for blogs and Rookwood for studios and companies. Plain CSS and JavaScript, no jQuery or Bootstrap, built for Core Web Vitals, each with its own sample data.

        See them →
      

      

        cli
        
A command line for everything

        
cli/joomla.php uses the command names of Joomla 4 and later, and adds many more: content, templates, databases, health checks and logs. JSON output and dry runs everywhere.

        The command line →
      

      

        ai
        
A built-in MCP server

        
Claude, ChatGPT, Gemini, Qwen, Kimi, GLM and other AI assistants can work with your site through the Model Context Protocol. Read-only unless you allow more, and every change is logged.

        How it works →
      

      

        editor
        
TinyMCE 8

        
The latest TinyMCE is the default editor of new sites: image uploads by dropping or pasting, a toolbar builder per user group, 61 languages. TinyMCE 4 stays as "legacy" for existing sites.

      

      

        administrator
        
Quality of life

        
A new responsive login page, one-click Clean Cache in the status bar (plus Clean Everything and Global Check-in for administrators), Install from Web back as the first tab, and Help buttons that work again.

      

      

        updates
        
What's new, in the backend

        
Post-installation Messages now tell the story of this distribution, one message per release since v3.11, instead of stock Joomla's notes from the 3.2–3.10 era.

      

      

        php 8.5
        
Thousands of fixes

        
Long-standing bugs in the API sorted, database errors handled as Joomla expects on PHP 8.1+, and every PHP deprecation we could find removed — including thousands while Smart Search indexes.

      // why this exists
      
Official support ended. We kept going.

      
According to market share estimates (as of May 2026), Joomla 3.x is currently used on more than 50% of all installed Joomla sites worldwide. However, official support for Joomla 3.x ended in February 2025 (counting the eLTS program).

      
So we're actively developing Joomla 3.x UTD as an up-to-date distribution of the Joomla 3.x content management system, built to ensure code security, support modern PHP & MySQL/MariaDB versions & fix any broken behaviour that never got sorted before the release of newer major versions of Joomla.

Upgrade in place. Or start fresh.

        
One rolling release, one download path that never changes. Point your backend at our update feed, extract on top of an existing Joomla 3.x site, or install a new one in about a second.

        existing sites · cli
        
One-liner over SSH

        
On a typical Linux server, cd into your Joomla site's folder and run:

        

          
bash

          
wget -qO- https://github.com/joomlaworks/joomla-3.x/archive/refs/heads/main.tar.gz | tar -xz --strip-components=1 && rm -rf installation .github .gitignore *.md

        

        
Extracting the zip manually? Remember to remove the /installation folder afterwards.

      

      

        new sites
        
Fresh install

        
Extract the latest rolling release where you want the site to be and open it in a browser, or install from the command line on SQLite (PHP 7.4+ with pdo_sqlite), in an empty folder:

        

          
bash

          
wget -q …/rolling/joomla-latest.zip && unzip -q joomla-latest.zip && rm joomla-latest.zip && php cli/joomla.php core:install --site-name="My Site" --admin-email=me@example.com --admin-username=admin

        

        Download joomla-latest.zip
        
Add --sample-data=news, blog or studio. Built and tested for Linux/BSD; XAMPP or MAMP should work, but aren't tested.

      

    

  






  

    

      

        // command line & ai
        
A CMS your scripts and AI assistants can drive

        
A new command line, cli/joomla.php, with the command names of Joomla 4 and later and many more of its own. Every command speaks JSON, so scripts and AI agents can work with your site directly — and the built-in MCP server lets assistants such as Claude, ChatGPT or Gemini do it for you.

      

      MCP setup guide →
    

    

      
    
        
  • Full content managementArticles, categories, tags, modules and menu items: list, create, change, publish, trash and delete, saved as the administrator saves them, acting as an account whose permissions apply (--as).
    • 
        
  • Templates, databases, healthTemplate files and options with undoable changes and backups, database:convert between MySQL, PostgreSQL and SQLite in any direction, site:health, logs and the action log.
    • 
        
  • Safe by defaultDry runs on every command that changes something. The MCP server is read-only unless you add --allow-write; anything that puts code on the server also needs --allow-code.
    • 
        
  • TraceableEvery change is recorded in the User Actions Log, as made through the command line or MCP. Secrets are masked, and server file paths are never offered to the assistant.
    • 
      

      

        

          
connect claude code

          
claude mcp add joomla -- php /path/to/site/cli/joomla.php mcp:serve
# let it make changes too: add --allow-write at the end
# a site on another server: run it over ssh
claude mcp add joomla -- ssh user@example.com php /path/to/site/cli/joomla.php mcp:serve

    // compatibility
    
It runs where your sites already live

    
PHP 7.4 is the recommended baseline, not a hard cutoff. Older servers keep getting security patches while you plan the move.

    

      

        
PHP 8.5

        
Modern stacks

        
Compatible with PHP up to 8.5, MySQL 8.0, 8.4 and 9.x, current MariaDB and PostgreSQL 18. Deprecations are fixed as they're reported.

        Database support →
      

      

        
PHP 7.1+

        
Older hosts

        
Sites on PHP 7.1 through 7.3 are still offered updates through the Joomla Update component. PHP 7.0 and below is not supported. Moving from 5.6 or 7.x to 7.4 is typically a safe switch — just check your extensions and templates aren't holding you back.

      

      

        
CentOS 7?

        
Stuck servers

        
A server hosting Joomla sites on PHP older than 7.2 may be stuck on CentOS 7/cPanel, no longer supported by either vendor. Switching to this distribution takes you closer to upgrading — e.g. AlmaLinux 8 with cPanel, or Ubuntu 22.04+ with Ondřej's PHP repos.

      

    

  






  

    // databases
    
Every major database, tested

    
Joomla 3.x was always centred on MySQL/MariaDB. Since v3.17, all of its databases simply work: PostgreSQL and SQL Server are tested again, and SQLite is new. The core works on every one of them; many third-party extensions only ship MySQL/MariaDB database scripts, so check those before moving a site to PostgreSQL or SQL Server.

    

      

        
DatabaseMinimumStatus

        
          
MySQL5.5.3Tested and actively supported (5.7 or newer recommended); 8.0, 8.4 and 9.x on their default settings

          
MariaDB5.5Tested and actively supported (10.11 and 11.8 tested)

          
PostgreSQL9.0Tested with both drivers since v3.17 (16 or newer recommended, preferably 18)

          
SQL Server / Azure SQL2008 R2Inherited from stock Joomla 3.x; tested since v3.17 on SQL Server 2022 with both drivers (core only: few extensions support it)

          
SQLite new3.37.0Experimental, PHP 7.4+. Runs MySQL SQL through an emulation layer, so core and extensions work unchanged; tested on 3.37.2 and 3.46.1

        
      

    

    
The installer enforces these minimums. Once a site runs 3.16 or newer, it won't be offered further updates while its database is below them, and sees a notice in Joomla Update instead.


    

      

        mysql 8.0 · 8.4 · 9.x
        
No native passwords needed

        
MySQL's default authentication since 8.0 (caching_sha2_password) is handled by PHP itself, so my.cnf needs no changes. MySQL 9 removed mysql_native_password: before upgrading, switch users created with it to the default.

        

          
sql

          
ALTER USER 'username'@'host' IDENTIFIED WITH caching_sha2_password BY 'password';

        

      

      

        sqlite · experimental
        
The site in one file

        
For development, testing and small to medium sites: SQLite handles one write at a time, so busy sites with many simultaneous writers should stay on MySQL/MariaDB. SQLite sites use PHP sessions, so browsing doesn't write to the database.

        

          
move a site to sqlite, and back

          
php cli/joomla.php database:convert --to=sqlite
php cli/joomla.php database:convert --to=mysqli

        

      

      

        mysql & mariadb
        
Recommended setting

        
For maximum compatibility with Joomla 3.x extensions, in both MySQL and MariaDB. MariaDB keeps mysql_native_password as its default, which works as before.

        

          
my.cnf

          
sql_mode = ""

Security fixes, backported as they land

        
Every official Joomla security release is reviewed against this codebase. When the vulnerable code exists in 3.x, it gets fixed here — including issues listed upstream as affecting only Joomla 4.0 and later. And we audit 3.x ourselves: most of v3.17's 22 fixes were in stock Joomla 3 all along.

Little WAF. An opt-in system plugin (since v3.16) that filters known attack signatures against abandoned or historically vulnerable third-party extensions before any component runs, with filters for Sourcerer-style {source} URL injection and Modules Anywhere-style {module}/{modulepos} tags. Since v3.17 it also checks form data and encoded spellings, and each filter only acts while its extension is installed. Disabled by default; more filters will be added over time.

    

    
Advisories that don't apply — because the vulnerable feature doesn't exist in 3.x — and issues already covered by earlier hardening are documented in the changelog as well.

    // long-term plan · a different project
    
A leaner fork is on the way

    
A new fork based on Joomla 3.x is a work in progress — but very, very active. When released, it will feature:

    

      
01 · core
Stripped down
Joomla 3.x with all non-essential extensions removed.

      
02 · php
PHP 7.4 → 8.x
Fully compatible with PHP versions from 7.4 to 8.x and so on.

      
03 · database
Latest MySQL & MariaDB
Fully compatible with the latest versions of both.

      
04 · content
K2 for content
com_content and anything related is removed entirely, decoupling content features from a solid CMS base that keeps true backwards compatibility with past releases of the fork.

      
05 · admin
Admin refresh
A refreshed administrator experience.

      
06 · js
Modern JS only
Gradual jQuery/MooTools removal.

      
07 · future
Built to last
Gradual codebase modernization to support future PHP & MySQL/MariaDB versions without much effort.
