                        // new in v3.18
                        
A lighter core, a stronger site

                        
A new administrator template, Markdown and Blocks editors, a much better Media Manager, PDF files, Little WAF on by default and caching that holds up under real traffic, with no jQuery, MooTools or Bootstrap left in the core. On top of that, 12 security fixes and a long list of bugs stock Joomla 3 never got round to.

Prothero, the new administrator template

                        
Isis' markup with a minimal black and white look, so every extension made for Isis works unchanged. It's the default on new sites, and sites updating from Isis get it too (Isis stays installed).

                        
    
                            
  • Light and dark colour schemes, automatic by default
    • 
                            
  • A choice of colours for the menu bar, and a matching login page
    • 
                            
  • Lists that fit narrow screens, a phone menu in two columns, touch reordering

                        content
                        
New editors, and PDF files everywhere

                        
Write in Markdown or in blocks, next to TinyMCE 8, and switch between them while you edit without losing unsaved changes. Content is always saved as HTML.

                        
    
                            
  • Markdown (EasyMDE): a preview, side by side, drag and drop uploads
    • 
                            
  • Blocks (Editor.js): headings, images, embeds, tables, code; templates add blocks of their own, with a desktop, tablet and phone preview
    • 
                            
  • PDF files: a viewer on the site, and a new PDF button in every editor that picks or uploads the file and inserts it with a preview
    • 
                        

                    

                    

                        

                            

                                
                                
                                
                                
                                
                                
                            

                        

                    

                

                

                    

                        modules
                        
Modules for HTML, blocks and code

                        
Two new module types and an updated one, for the site and the administrator, each edited in the editor that suits it.

                        
    
                            
  • Custom HTML (the old Custom module, renamed): always opens in TinyMCE, and runs content plugins by default, with an option that now says what it does
    • 
                            
  • Custom Blocks: a module position's content written in the Blocks editor, rendered by the template's block layouts
    • 
                            
  • Custom Code: your own HTML, CSS, JavaScript, embeds or verification snippets, written in CodeMirror and output as they are

A Media Manager you'll enjoy

                        
Drag files in, crop, rename in place and preview everything, without leaving the folder you're in.

                        
    
                            
  • Drag and drop uploads, also in the image picker
    • 
                            
  • Cropping, free or 21:9 to 1:1, as a new file or over the original

                        caching
                        
A Page Cache built for real traffic

                        
The Page Cache plugin now has its own cache times for the home page and other pages, serves a stale copy while one visitor refreshes it, and tells browsers, Varnish and CDNs exactly how long a page is good for.

                        
    
                            
  • A page is built once, however many visitors ask for it at the same moment
    • 
                            
  • Campaign and social links (utm_*, fbclid, gclid...) get the cached page
    • 
                            
  • A stale copy instead of an error page when the site is struggling
    • 
                            
  • Age, s-maxage, stale-while-revalidate, stale-if-error and an X-Logged-In header for shared caches
    •

                        performance
                        
Faster from the first byte to the last script

                        
Less code to download, less work for the server, and more requests answered from the cache.

                    

                    
    
                        
  • No jQuery, MooTools or Bootstrap in the core. One shared plain JavaScript file does what they did; old names keep working for extensions.
    • 
                        
  • Leaner front end. Hammond, Finch and Rookwood load no framework at all, and the CMS's scripts move to the end of the page when nothing needs them earlier.
    • 
                        
  • Early Hints. Resource hints and preloads of every page's stylesheets and scripts go out as Link: headers, so a CDN can start fetching before the page is ready.
    • 
                        
  • Smaller files. The icon font cut to the icons in use (13 KB instead of 134 KB), Isis' stylesheets a third of their former size, no Less and no files for old Internet Explorer.
    • 
                        
  • Caching that scales. One build per page however many visitors ask, stale copies served while refreshing, tracking parameters sharing cached pages, and the file cache reading about 30% faster.
    • 
                        
  • Plugins in the right order. Little WAF, Redirect, Language Filter, Remember Me and Page Cache run first by default, so cached pages skip every other plugin's work.
    • 
                        
  • Optimised images. Editor uploads saved as WebP without metadata; Hammond, Finch and Rookwood use smaller copies in srcset and lazy images everywhere but the top of the page.
    • 
                        
  • Large sites. Smart Search indexes and looks pages up without scanning whole tables, and Memcached no longer slows down as the cache grows.
    •

                    // why we built this project
                    
Official support ended. We kept going.

                    
According to market share estimates (as of May 2026), Joomla 3.x is currently used on more than 50% of all installed Joomla sites worldwide. However, official support for Joomla 3.x ended in February 2025 (counting the eLTS program).

                    
So we're actively developing Joomla 3.x UTD as an up-to-date distribution of the Joomla 3.x content management system, built to ensure code security, support modern PHP & MySQL/MariaDB versions & fix any broken behaviour that never got sorted before the release of newer major versions of Joomla.

On a typical Linux server, cd into your Joomla site's folder and run:

                        

                            
bash

                            
wget -qO- https://github.com/joomlaworks/joomla-3.x/archive/refs/heads/main.tar.gz | tar -xz --strip-components=1 && rm -rf installation .github .gitignore *.md

                        new sites
                        
Fresh install

                        
Extract the latest rolling release where you want the site to be and open it in a browser, or install from the command line on SQLite (PHP 7.4+ with pdo_sqlite), in an empty folder:

                        

                            
bash

                            
wget -q https://github.com/joomlaworks/joomla-3.x/releases/download/rolling/joomla-latest.zip && unzip -q joomla-latest.zip && rm joomla-latest.zip && php cli/joomla.php core:install --site-name="My Site" --admin-email=me@example.com --admin-username=admin

                        

                        Download joomla-latest.zip
                        
Add --sample-data=news, blog or studio. Built and tested for Linux/BSD; XAMPP or MAMP should work, but aren't tested.

                    

                

            

        


        

            

                

                    

                        // command line & ai
                        
A CMS your scripts and AI assistants can drive

                        
A command line built for automation from the ground up: 101 commands covering content, templates, databases, health checks and logs, every one with JSON output and dry runs. The built-in MCP server lets AI assistants such as Claude, ChatGPT or Gemini work with your site for you. Where Joomla 4 or newer has a command, ours keeps its name, so their users feel right at home.

                    

                    AI & CLI guide →
                

                

                    
    
                        
  • Full content managementArticles, categories, tags, modules and menu items: list, create, change, publish, trash and delete, saved as the administrator saves them, acting as an account whose permissions apply (--as).
    • 
                        
  • Templates, databases, healthTemplate files and options with undoable changes and backups, database:convert between MySQL, PostgreSQL and SQLite in any direction, site:health, logs and the action log.
    • 
                        
  • Safe by defaultDry runs on every command that changes something. The MCP server is read-only unless you add --allow-write; anything that puts code on the server also needs --allow-code.
    • 
                        
  • TraceableEvery change is recorded in the User Actions Log, as made through the command line or MCP. Secrets are masked, and server file paths are never offered to the assistant.
    • 
                    

                    

                        

                            
connect claude code

                            
claude mcp add joomla -- php /path/to/site/cli/joomla.php mcp:serve
# let it make changes too: add --allow-write at the end
# a site on another server: run it over ssh
claude mcp add joomla -- ssh user@example.com php /path/to/site/cli/joomla.php mcp:serve

“Check the site's health, then draft an article about our autumn opening hours in the News category — leave it unpublished for me to review.”

                            
It runs site:health, finds the category, and creates the article as an unpublished draft, logged in the User Actions Log.

                // compatibility
                
It runs where your sites already live

                
PHP 7.4 is the recommended baseline, not a hard cutoff. Older servers keep getting security patches while you plan the move.

                

                    

                        
PHP 8.5

                        
Modern stacks

                        
Compatible with PHP up to 8.5, MySQL 8.0, 8.4 and 9.x, current MariaDB, PostgreSQL 18 and SQLite. Deprecations are fixed as they're reported.

                        Database support →
                    

                    

                        
PHP 7.1+

                        
Older hosts

                        
Sites on PHP 7.1 through 7.3 are still offered updates through the Joomla Update component. PHP 7.0 and below is not supported. Moving from 5.6 or 7.x to 7.4 is typically a safe switch — just check your extensions and templates aren't holding you back.

                    

                    

                        
CentOS 7?

                        
Stuck servers

                        
A server hosting Joomla sites on PHP older than 7.2 may be stuck on CentOS 7/cPanel, no longer supported by either vendor. Switching to this distribution takes you closer to upgrading — e.g. AlmaLinux 8 with cPanel, or Ubuntu 22.04+ with Ondřej's PHP repos.

                    

                

            

        


        

            

                // databases
                
Supported databases

                
Joomla 3.x was always centred on MySQL/MariaDB. Since v3.17, all of its databases simply work: PostgreSQL and SQL Server are tested again, and SQLite is new. The core works on every one of them; many third-party extensions only ship MySQL/MariaDB database scripts, so check those before moving a site to PostgreSQL or SQL Server.

                
    
                    
  • MySQL5.5.3 → 9.7 tested
    • 
                    
  • MariaDB5.5 → 11.8 tested
    • 
                    
  • PostgreSQL9.5 → 18 tested
    • 
                    
  • SQL Server & Azure SQL2008 R2 → 2025 tested
    • 
                    
  • SQLite3.37 → 3.46 tested · experimental
    •

The installer enforces these minimums. Once a site runs 3.16 or newer, it won't be offered further updates while its database is below them, and sees a notice in Joomla Update instead.


                

                    

                        mysql 8.0 · 8.4 · 9.x
                        
No native passwords needed

                        
MySQL's default authentication since 8.0 (caching_sha2_password) is handled by PHP itself, so my.cnf needs no changes. MySQL 9 removed mysql_native_password: before upgrading, switch users created with it to the default.

                        

                            
sql

                            
ALTER USER 'username'@'host' IDENTIFIED WITH caching_sha2_password BY 'password';

                        

                    

                    

                        sqlite · experimental
                        
The site in one file

                        
SQLite runs in WAL mode: visitors keep reading while a write happens, and writes queue for their turn instead of failing. Most writes take milliseconds, and SQLite sites keep sessions in PHP, so browsing writes nothing to the database. With caching on, that makes it a practical choice for small to medium sites, not just development and testing. Sites with many simultaneous writers (busy shops, forums) are better on MySQL/MariaDB.

                        

                            
move a site to sqlite, and back

                            
php cli/joomla.php database:convert --to=sqlite
php cli/joomla.php database:convert --to=mysqli

                        

                    

                    

                        mysql & mariadb
                        
Recommended setting

                        
For maximum compatibility with Joomla 3.x extensions, in both MySQL and MariaDB. MariaDB keeps mysql_native_password as its default, which works as before.

                        

                            
my.cnf

                            
sql_mode = ""

Little WAF. An opt-in system plugin (since v3.16) that filters known attack signatures against abandoned or historically vulnerable third-party extensions before any component runs, with filters for Sourcerer-style {source} URL injection and Modules Anywhere-style {module}/{modulepos} tags. Since v3.17 it also checks form data and encoded spellings, and each filter only acts while its extension is installed. Disabled by default; more filters will be added over time.

                // long-term plan · a different project
                
A leaner fork is on the way

                
A new fork based on Joomla 3.x is a work in progress — but very, very active. When released, it will feature:

                

                    
01 · core
                        
Stripped down

                        
Joomla 3.x with all non-essential extensions removed.

                    

                    
02 · php
                        
PHP 7.4 → 8.x

                        
Fully compatible with PHP versions from 7.4 to 8.x and so on.

                    

                    
03 · database
                        
First-class databases

                        
First-class support for MySQL, MariaDB, PostgreSQL and SQLite. The SQL Server and Azure SQL drivers will be dropped.

                    

                    
04 · content
                        
K2 for content

                        
com_content and anything related is removed entirely, decoupling content features from a solid CMS base that keeps true backwards compatibility with past releases of the fork.

                    

                    
05 · admin
                        
Admin refresh

                        
A refreshed administrator experience.

                    

                    
06 · js
                        
Modern JS only

                        
Further JavaScript work: clean-room versions of the scripts we ported from jQuery and MooTools, for a smaller payload overall, and possibly htmx in the administrator for a desktop-like feel.

                    

                    
07 · future
                        
Built to last

                        
Gradual codebase modernization to support future PHP & MySQL/MariaDB versions without much effort.

                    

                    
08 · agentic
                        
A truly agentic CMS

                        
AI agents working alongside editors, developers and site owners. The command line and MCP server of Joomla 3.x UTD are the seed: the integrations to come grow from them.
